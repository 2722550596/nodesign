# 核心：世界不在对话里，世界在文件里

这是这个形态唯一的地基，别的规矩全从它长出来。

对话是会消失的。它会被压缩，会因为上下文太长而变贵，用户关掉窗口它就没了。
所以**任何你希望明天还在的东西，写进文件**。反过来，任何写进文件的东西，
你下一轮不需要就别读进来。

一个具体的检验：**假装这一轮结束后会话就被删掉，明天开一条新的接着写。**
只靠 `世界/` 里那些文件，接得上吗？接不上说明有东西还只活在对话里，现在就落盘。

## 目录：文件夹树就是地图

```
tasks/<世界名>/
├── 世界.md              世界书。设定的稳定部分。冻结层，平时不改
├── 事件.md              变化追加在这里，结算时才并进世界书
├── 世界/                空间结构根，文件夹树 = 地图
│   ├── 王城/
│   │   ├── 地点.md
│   │   ├── 背景.png      这个地点的画面
│   │   └── 大殿/
│   │       ├── 地点.md
│   │       └── 艾琳/
│   │           ├── 角色.md        当前状态。每场都可能变
│   │           ├── 背景故事.md    写一次，基本不动
│   │           ├── 经历.md        只增不减
│   │           └── 立绘/
│   │               ├── prompt.md  生图用的固定描述，冻结
│   │               ├── 立绘.png
│   │               └── 表情-怒.png
│   └── 角色库/
│       ├── 容器.md      收纳，不是地点。存暂时不出场的人
│       └── 老铁匠/
├── 关系/
│   └── 艾琳与维克多.md
├── 场记/                RP 的产出
├── 正文/                小说的产出
└── 大纲/                小说的规划
```

**类型看内容不看名字。** 文件夹里有 `地点.md` 就是地点，有 `角色.md` 就是角色，
有 `容器.md` 就是收纳容器。所以文件夹叫什么都行，改名不会弄坏任何东西。

**每一层地点都要有自己的 `地点.md`。** 漏了那一层会被标成「未声明」，用户看得见。

**角色在哪个文件夹，就是在哪个地方。** 让人物换地方就是移动文件夹，不需要
在别处再记一遍。一个人同时只能在一处，这是文件系统保证的，别绕过它。

## 上下文纪律：每轮只读该读的

这条不守，成本会随着世界变大线性上涨，写到第四十章一轮的钱够前面写十章。

**每轮读**：当前地点的 `地点.md`、**在场**角色各自的 `角色.md`、在场两人之间
存在的关系文件、场记或正文的末尾一段、本章大纲（或 `悬线.md`）。

**每轮不读**：`背景故事.md`、`经历.md`、不在场角色的任何东西、`世界.md` 全文
（第一次读过之后它就在上下文里了，别反复 Read）。

要用旧事就**检索**，别整份读进来。经历文件会长到几千行，一次全读就把预算吃光。

**在场 = 进上下文。** 用户把角色拖出场景，就是明确表示不想让他影响这一段。
尊重这件事：他的状态不该再进你的判断。

## 世界书冻结，变化追加

`世界.md` 是稳定层，**平时不要改它**。它每改一次，后面所有轮的缓存就作废重建一次。

世界级的变化（王死了、边境开战、某个组织覆灭）先写进 `事件.md`。
只有到结算的时候，才把 `事件.md` 折叠进 `世界.md` 并清空。

人物级的变化不进 `事件.md`，直接改那个人的 `角色.md`。

## 结算：换会话的落点

一章写完、一场演完、或者用户说收工，做一次结算，一次做完四件事：

1. 把 `事件.md` 折叠进 `世界.md`，然后清空 `事件.md`
2. 经历太长的角色做压缩：**近期原文保留，往事压成摘要**。不要整份重写成摘要，
   那会把"她当时说了那句话"这种让角色立住的细节洗掉
3. 小说写 `大纲/章-N-实际.md`（真实走向，跟当初的计划分开存）
4. 给下一段写个骨架

结算之后建议结束会话。下一次冷启动只靠文件重建，这是防成本涨、防压缩丢细节的
主要手段。**所以结算的产出必须足够让明天的自己接得上。**

# 玩法一：写小说

## 大纲三层，不是一层

只写章大纲，写到第四十章会局部合理、整体崩。

- `大纲/全书.md` — 走向和终点。很少动
- `大纲/卷N.md` — 这一卷要完成什么
- `大纲/章-N-计划.md` — 开章前写，**写完不改**

**下一章的规划读的是 `章-N-实际.md`，不是 `章-N-计划.md`。** 章写完总会偏离计划，
拿当初的计划去推下一章，偏差会一路滚下去。

## 正文是连续散文

`正文/003-雨夜.md`，一章一个文件。不要按说话人切成条目 ——
好的叙述是把动作、对白、心理揉在一起的：

> 「你来了。」她没抬头，手里的刀还在削。

这种交错一旦按说话人切槽就没了。散文就写散文。

# 玩法二：角色扮演

## 你写除用户之外的所有人

用户扮演一个角色，那个角色的话和行动由用户决定。**不要替他说话，不要替他做决定。**
他没说的事就是没发生。

## 场记格式（这是数据格式，照着写）

`场记/007-雨夜的酒馆.md`：

```markdown
## 007 · 雨夜的酒馆
> 地点：世界/王城/大殿
> 在场：艾琳、维克多

**艾琳**：你来了。

她没抬头，手里的刀还在削。

**维克多**：外面雨大。
```

规则只有两条：**说话是 `**名字**：内容` 单独成段，旁白是普通段落。**
这个格式后面要被解析成卡片，说话人是数据不是排版，别自创写法。

## 悬线代替大纲

RP 是即兴的，没有大纲。但 `悬线.md` 要维护：**还没解决的事、埋下没收的伏笔、
谁欠谁一个交代。** 这是防止跑十几轮之后所有线索一起蒸发的唯一办法。

## 每回合收尾：更新在场角色的状态

写完场记不等于这一轮写完了。收尾前问一句：**这一轮有没有改变谁的处境、情绪、
或者他知道的事？** 有就改那个人的 `角色.md`，没有就别动。

这一步最容易漏，因为场记一写完就觉得已经交代过了。但要看清楚这两个文件的
分工：

- **场记是记录**，写给人看的，下一轮**不会**进你的上下文
- **`角色.md` 是状态**，下一轮**会**进你的上下文

也就是说，只写进场记的变化，下一轮的你根本看不见。她刚才为什么警惕、
他现在坐在哪、谁欠了谁一句解释，如果只留在场记里，再演三轮你就会写出一个
跟前面对不上的她。**人设崩掉不是因为忘了设定，是因为状态没跟着走。**

不用写长，一两句就够：

```markdown
## 当前状态
在吧台后擦杯子，维克多坐在对面，刚给他倒了杯热的。
提到钟楼十三下时明显顿了一下 —— 她知道点什么，但还没打算说。
```

# 立绘：一致性靠参考图，不靠描述

`立绘/prompt.md` 里那段角色外观描述**写一次就冻住，不要再改**。
一改，同一个角色跨图就不像同一个人了。

第一张立绘生成出来后选定一张当**身份参考图**，之后所有的立绘和表情差分都把它
作为 `referenceImages` 传进 `generate_image`。光靠文字描述保不住一致性，参考图才行。

表情差分用九宫格一次出多个动作再切图，切出来的文件名固定（`表情-怒.png`
这种），方便复用。

# 起手

用户说想写故事或者想玩角色扮演时，**先问清楚一件事：这是要写出来的，还是要演的。**
两种玩法共用同一个世界，但产出完全不同，开头就走错会白做很多。

然后建 `tasks/<世界名>/世界.md`，先把设定的骨架写下来，再铺 `世界/` 下的地图。
先建人后建地点也可以，角色会暂时挂在 `世界/` 根下，等地点建好再移进去。
