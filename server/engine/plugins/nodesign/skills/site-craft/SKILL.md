# 核心守则：先定气质，再铺页

跟 deck 同一条路：**试作 → 给看 → 改 → 用户说"就这个" → 锚定 → 铺开**。

区别在试作做什么。deck 试作一页封面；站点试作**首页的上半屏加一段正文** —— 站点
的气质八成由正文排版决定，只做个漂亮 hero 给用户看，等铺到正文那天他会说"怎么
跟我想的不一样"。试作放 `_drafts/<名字>.html`，各自渲成卡并排给用户挑。

## 骨架从一个问题长出来

动手前先答：**访客带着什么来，你想让他带着什么走？**（做成一件事？记住一个印象？
读完一篇？玩明白一个东西？）答案定了，骨架自己会长出来 —— 要一个动作就把全站
收束到那个动作，要一个印象就让首页本身成为印象，要人读下去就把一切让位给正文。

几个常见答案长出来的样子，当参考不当分类：

- 「做一件事」→ 单页长滚动，一句话开场 → 证据 → 一个行动点，导航可以没有
- 「认识一个人」→ 首页是气质本身，作品/文章各一页；个性 > 信息效率
- 「读下去」→ 首页即目录（标题列表就很好），正文页才是全站核心
- 「搞懂一个东西」→ 概览 + 分主题子页，导航要清楚，别炫技

不在这几种里的站（活动邀请 / 展览预告 / 互动玩具 / 纪念页……）多得是 —— 别硬套，
回到那个问题现推。骨架跟上面撞了是巧合，没撞是正常。用户没说清他要什么，
问一句，或按 brief 推两个不同答案做进试作里给他挑。

## 排版系统：气质的地基

**三个数定生死**（写进 `:root`，锚定时固化）：

- **字距** `letter-spacing`：中文正文 0.05~0.08em 之间差别很大
- **行高** `line-height`：中文正文 1.75~1.95，比英文站需要的高
- **正文宽** `max-width`：中文 780~900px，一行 35~45 字最舒服

这三个数一改就是换气质，改配色只是换衣服。

**标题梯度**：两级够用（页题 + 节题），最多三级。相邻级差要明显（1.6× 以上），
差 20% 的两级读者分不出来，等于没有层级。标题跟正文拉开的方式不止字号 ——
字重、颜色深浅、上方留白，选一两个维度用足，比每级都放大一点有效。

**间距节奏是长页气质的另一半**：段间距 < 节内块间距 < 节间距，比例拉开
（比如 1 : 2 : 4~6）。节与节之间敢留大白 —— 长页的"呼吸感"几乎全靠节间距，
挤在一起的精致排版读起来还是喘不过气。全篇用一套间距刻度（如 8 的倍数），
别每处现拍一个数。

## 色彩方法

- **一个主色 + 一套中性灰**，够做绝大多数站点。主色用在链接、细线、选中态这些
  小面积处才显贵；大面积铺主色是海报做法，不是网页
- **文字别用纯黑纯白**：深色文字往主色方向偏一点（比如 #1a1a1a 带一丝暖或冷），
  背景白也可以是米白 / 暖白。整站的"温度"就是这么来的
- **中性灰要成梯度**：正文、次要文字、注脚、分隔线、底色，各取一档，全站复用。
  灰是排版里用得最多的颜色，梯度乱了整站就脏
- 深浅模式不用都做，跟用户确认默认哪种就好

## 图像手法

三种用法，按页面角色选：

1. **全幅大图**：hero 或章节开场。图上压字时只压文字落脚的局部（局部渐变），
   别用整层半透明黑罩压全图
2. **抠图叠层（贴纸感）**：`remove_background` 抠出透明主体，当**版面元素**用而
   不是当"配图"——人物骑在分隔线上、吉祥物探出正文边缘、物件散落在标题周围。
   加一点微旋转（-3°~3°）和阴影就有手作拼贴的味道。个人站和产品页的差异化利器，
   具体配方 Read `patterns/cutout-collage.md`
3. **装饰性小元素**：小图钉、胶带、手绘箭头、纹理角标。少量、有主题一致性，
   跟站点气质同源（复古站用纸纹胶带，科技站用坐标刻度线）

生图走 `generate_image`（cookbook 首次调用时注入），抠图走 `remove_background`。
图先落任务本地 `assets/` 再引用。没有合适的图时，大字排版本身就是视觉主角，
不要拿 emoji 或免费图凑数。

## 动效预算

CDN 库随便拉（gsap / lenis / three / alpine / htmx），但动效是调味不是主菜：

- **一页最多两种动效语言**：比如"滚动淡入 + hover 微移"就是全部。首屏可以有
  一处大的（打字机 / 视差 / 3D 背景），后面全篇克制
- 滚动揭示别每个元素都做，按**节**做；时长 0.4~0.7s，缓动统一一个函数
- `prefers-reduced-motion` 尊重一下，media query 三行的事
- 动效永远不该让人等：进场动画挡住内容超过 1s 就是负资产

## 中文排版基线

- 标点用**全角**（，。：；？！……），半角逗号冒号在中文里很扎眼
- 字体链每段 latin family 后面必须跟 CJK family：
  `'Inter', 'PingFang SC', 'Noto Sans SC', system-ui, sans-serif`
  少了 CJK 那段，换台机器中文就掉到系统默认字体
- 细字重（300 以下）在 13~15px 的汉字上会糊笔画。气质靠行高字距留白撑，
  不靠细体 —— 大标题（28px+）用细体没问题

## 响应式

一到两个断点通常够（`max-width: 860px` 单栏化是最常用的一个），复杂布局需要
第三个就加，别为档位而档位。**做完必须自己看过真实宽度**：
`screenshot_canvas { device: 'mobile' }` 是真的按 390px 渲染 —— 媒体查询有没有
生效只有这样才看得出来。抠图叠层在窄屏最容易出事（盖住正文），mobile 档重点看它。

## 工程形态

一份 `index.html` + 一份 `style.css` 起步，多页同目录加 `.html`。简单站点这样
就够，别为它们引工程。真需要构建（几十篇 md 的博客、组件复用的多页站）就上：
Astro / 11ty / 自写脚本都行，装包跑得通，产物落 `dist/`（系统按约定自动认）。
唯一硬约束：**产物必须是纯静态文件**，SSR / 常驻进程不行。

样式建议集中在一份 CSS 里 —— 用户自己才改得动；utility class（Tailwind 等）
散在几百个标签上，改行高要改一百处。用户点名要就用。

## 反默认清单

下面这些是 AI 生成网页的统计均值 —— 出现任何一条，说明那里**没有做设计决策**，
只是滑进了模型的默认输出。它们不是错，是平庸：

| 均值 | 它替代掉了什么思考 |
|---|---|
| 全宽 hero + 居中大标题 + 渐变背景 | 这一屏到底想让人记住哪句话 |
| 三张等高功能卡片平铺 | 这三件事真的同等重要吗 |
| emoji 当图标 | 这里需要图吗？需要的话是什么图 |
| box-shadow 卡片堆叠 | 内容之间的关系用线还是留白表达 |
| "Get Started" / "了解更多"按钮组 | 用户此刻真正想去哪 |
| 每段配一个渐变色块 | 主色到底是哪个、用在哪 |

写完扫一眼，命中的地方回去把那个被跳过的问题答了 —— 答案有时候恰好就是默认
形态，那也行，但要是选出来的，不是滑出来的。

## 铺开时

- 每一页只回答一个问题，导航里说得清它是什么
- 页与页之间用**相对链接**（`about.html`、`posts/x.html`），绝不用 `/about.html`
- 站内链接指向的文件必须真的存在 —— `list_pages` 会给断链清单，做完看一眼
- 铺到一半发现锚不对，停下来跟用户说，不要悄悄漂

## 上线

用户明确说「发布 / 上线 / 挂到公网」时才动 `publish_site`（发公网是用户的决定，
不是你的）。要点：

- `publish_site({ task, action: 'publish' })` 发布或更新，返回永久 URL；重新发布
  地址不变，所以「改完更新一下线上」就是再调一次。
- 全新域名生效可能要一两分钟 —— 把这句话带给用户，别让他以为发失败了。
- 额度或权限被拒（试用账号 / 超出每人上限）就把错误原话转告，不要重试。
- 下线用 `action: 'unpublish'`，公网地址即刻失效。
