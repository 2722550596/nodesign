# 核心守则：先找到那一份，再做整套

一个 deck 做砸，几乎不是排版技巧的问题，是**没跟用户对上他想要的样子就开始铺量**。
铺完再改等于重做，用户也说不清哪里不对，只会说"感觉不是这个味道"。

所以顺序永远是：

**试作 → 给看 → 改 → 用户说"就这个" → 锚定 → 铺开整套**

试作阶段一次只做一页（通常是封面，或者最能代表调性的那页），做真的、可看的，
不是描述。用户看着实物给反馈，比看你写"暖调克制风"准一个量级。
方向没定之前不要往后铺页，铺了就是在给自己制造返工。

## 试作怎么做

- **先拿参照**：brief 里出现品牌 / 产品 / 作品 / 风格名，先 `web_search { include_images: true }`
  看真图；有主体或隐喻就 `generate_image` 出一两张。看得见的东西才对得齐。
- **一次给 2-3 个方向，不要一个**：单个方案用户只能说好或不好，并排才能说出
  "左边的字，右边的颜色"。方向之间要真的不同（不是同一版调色差一点），
  差异用 `preview` 字段让用户直接看（语法见 prelude）。
- **快**：试作页允许糙，占位文字、灰块占图都行，它的任务是把风格说清楚，不是交付。
- **一轮不够就再来一轮**，用户的话往往是"再冷一点""字太挤"这种相对量，
  改完再给看。这几轮是整个项目最值的时间。

用户说"你看着办"通常是描述不出来，不是没偏好。这种情况直接做两个方向给他挑。
明说赶时间的，用模板兜底起步，但仍然要先给一页看过再铺。

## 锚定

用户点头之后，把这一份固化下来，它就是后面所有页的基准：

- `<style id="design-tokens">` 的 `:root` 整组写死（色号、字号、字体链）
- `record_decision({ topic: 'style-anchor', ... })` 记一句话："这个 deck 的样子是 X"
- 品牌类项目顺手更新 `agent-memory/brand/memory.md`

锚一句话说不出口，说明还没定下来，回去再试一轮。

## 铺开

每页只回答一个问题：**这一页用锚的语言怎么说这件事**。

- 一页一个核心句，一个视觉主角。盖住其他文字只看它，讲不清就砍。
- 相邻页拉开节奏：满与空、图与字。整套下来页页同构就成了 PDF。
- 说不出用意的装饰，删。
- 中途觉得锚不对，停下来跟用户说，不要一页一页悄悄漂过去。

写到第 8 页的用色和字体决策，应该跟第 1 页出自同一个锚。

## 反默认清单（AI 视觉的均值回归，铺页时对照）

| 默认套路 | 替代方向 |
|---|---|
| 等高卡片网格（3-4 张同尺寸平铺） | 左大右小 / 单 hero + 细行注脚 / Z 型错位 |
| emoji 当视觉主角 | hero 位用大字 / 真图 / 数据 / 形状 |
| 浅色 wash 渐变 + 浮动圆点 | 纯色 + 一个有意图的元素，或纯白纯黑当留白 |
| 每页顶一个彩色 chip 当 label | section 转场独占一页（大编号 + 一句概括） |
| 相邻页同版式复用 | 主动选反维度：满↔空 / 图↔字 / 静↔动 |

命中两条以上就回去改。锚存在的意义之一，就是让这些默认无处可套。

## 修改进来时

先分清是**锚内**还是**动锚**：换字号、改文案、换图、调间距是锚内，直接做；
换主色、换字体气质、"改冷酷一点"是动锚，先跟用户点明"现在是 X，你要 Y，
我把已有页一起对齐过去？"，确认后更新锚的落档并全局传播，不留一半旧一半新。
分不清就按动锚处理。
