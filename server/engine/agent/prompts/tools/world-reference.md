# 世界形态技术参考

这份讲的是**机制**：文件放哪、什么东西被谁读走、哪些操作会花钱。
方法论（怎么建世界、怎么演、状态怎么跟着走）在 `world-craft` skill 里，用 Skill 工具加载。

## 判定

任务根有 `世界.md` 就是 world 形态。这个文件同时是判定证据和入口，别删也别改名。

world 形态**独占整个任务**：即使任务里有 `.html`（导出的仿书、临时预览页），
也不会派生出 deck 或 site 卡。所以预览页随便写，不会污染画布。

## 节点判定：内容证据

`世界/` 之下每一层文件夹，看它装着什么来定类型：

| 装着 | 类型 | 说明 |
|---|---|---|
| `地点.md` | 地点 | 可以套子地点，可以装角色 |
| `角色.md` | 角色 | 只装自己的东西，不装别的角色 |
| `容器.md` | 容器 | **不是地点**。收纳不在场的角色 |
| 都没有 | 隐式地点 | 底下有节点时自动补，标记为「未声明」 |

判定不看文件夹名，所以中文、空格、emoji 做名字都行，重命名不会弄坏任何东西。

两个边界：
- **角色文件夹不再往下递归**。所以 `立绘/` 不会被当成节点。
- **嵌套超过 8 层会被截断**，超出的部分不在地图上。层级摊平，别造深树。

## 图片的约定名

- 地点背景：`<地点文件夹>/背景.png`（也认 webp / jpg / jpeg）
- 角色立绘：`<角色文件夹>/立绘/立绘.png`，没有这个名字就取 `立绘/` 里排序第一张
- 表情差分：同目录，`表情-<名字>.png`

画布只加载 512px 缩略档，原图不上墙。

## 哪些工具对 world 不能用

`screenshot` / `read_page` / `query_elements` / `list_pages` / `get_computed_styles`
这五个是**浏览器工具**，需要一个能打开的 html 入口。world 没有，调用会被直接拒绝。

看世界的内容就直接 Read 文件：世界书是 `世界.md`，地图是 `世界/` 下的文件夹树
（用 Glob 看结构比 Read 快），角色状态在各自的 `角色.md`。

`generate_image` 正常可用，`referenceImages` 收图片不收 PDF。

## 每轮注入清单会告诉你什么

每一轮开头你会收到这个世界的一行说明：地点和角色计数、**在场名单**（角色名带
所在地点）、还没写 `地点.md` 的层、被截断的深层。

在场名单排除了收纳容器里的人。**在场 = 该进上下文**，这一行就是预算口径本身。

有一件事值得说清楚，因为它决定了你该往哪写：**下一轮进上下文的是 `角色.md`，
不是场记。** 场记是给人读的，状态文件才是给下一轮的你读的。
所以剧情里发生的变化如果只写进场记，下一轮的你看不见它。

## 版本与回退

每一回合结束，服务端会给这个任务目录自动落一条 git commit。所以：

- 世界的历史就是这个任务的 git log
- 回退到几轮之前 = checkout
- 换一条剧情线 = branch

**因此有损操作是安全的**，比如压缩经历、折叠世界书、覆写状态。原文都在历史里。
不要因为怕丢东西就不敢压缩，怕丢东西反而会让上下文涨到失控。

不要自己跑 `git commit`，服务端会做。

## 成本机制

这个形态里唯一会失控的东西是上下文长度，它直接换算成钱。

- 缓存读比首次读便宜十几倍，所以**同一份内容反复 Read 是纯浪费** —— 读过一次
  它就在上下文里了
- 缓存按前缀命中。**改 `世界.md` 会让它之后的所有缓存作废**，这就是为什么世界书
  要冻结、变化要追加到 `事件.md`、只在结算时折叠一次
- 换模型会让整条会话的缓存全部作废
- 上下文不会自己变短。会话越长每轮越贵，所以结算之后**建议开新会话**，
  靠文件冷启动

一个判断标准：如果你发现自己在读一份「可能有用」的文件，先停一下。
真需要的时候再读，比预先读进来便宜得多。
